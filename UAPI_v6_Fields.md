The v6 schema descriptions are unpopulated template placeholders (`src/unified/api/v6/files/oas.yaml`), so the description column comes from the published API docs for version `2026-06-01` (`fiskaly.unified-api.BE_EI-DE_EI-IT_EI.2026-06-01 (1).yaml`, BE_EI / DE_EI / IT_EI). Descriptions are matched to the v6 schema by name.

This is the shared source list for every format page. Each format page maps these paths; this page states only what the API accepts.

**How to read it**

- **UAPI field**: path relative to the section root. `[i]` marks an array element. **(new in v6)** means the path does not exist in API version 2026-06-01.
- **Req**: `R` required, `O` optional, relative to the parent object being present.
- **Applies when**: the discriminator values (`type`) under which the field exists, e.g. `recipients[i]` = BUSINESS.
- **BT per docs**: the EN 16931 business term fiskaly's API docs attach to the field. It states fiskaly's intent and is not checked against the standard. The format pages carry the verified BT.
- **[BE/DE/IT]** in a description marks country-specific documentation text (BE_EI, DE_EI, IT_EI).

**v5 → v6 changes relevant to e-invoicing**

- `entries[i].data.value.base`, `.discount` and `.surcharge` (each a single decimal in 2026-06-01) became objects with `.exclusive` and `.inclusive`. `doc/gobl/request2gobl.md` still uses the pre-v6 path `entries[i].data.values.discount`.
- The correction `reason` changed from free text to a typed object `{type: LEGAL_ERROR | RETURN | INSOLVENCY | UNCOLLECTIBLE | FACTUAL_ERROR | OTHER, text}` (changelog 2026-10-22).
- New in v6: per-entry `details.activity_code` (changelog 2026-10-08), the voucher and prepayment entry details, and the `DEPOSIT` and `MEAL_VOUCHER` payment types.
- Removed in v6: the `gender` attribute on person names, and the Italian Fisconline `credentials` (changelog 2026-10-20).
